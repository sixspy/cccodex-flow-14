## 幂等入库与回滚

入库按批次提交幂等钥条，去重与回滚在后台工作线程做齐，所有闸口由后端强制：

- **幂次策略当日钉死一种**：`skip_count`（遇幂等撞钥跳过并计数）或 `rollback_batch`（撞钥整批败绩并自行撤回到入库前）；钉死后当天不许更换，请求策略与钉死策略不符按「处置漂移」拦截（400）。
- **空钥条败绩**：整批含空钥条一律禁止入库（400），留败绩批次。
- **争用**：同流有在途入库/回滚时后到请求记争用败绩（409）；回滚未收尾不得再次开入库。
- **回滚单**：缘故必填，且不可由该批入库发起人本人发起（403）；回滚单正文在回滚详情可看。
- **幂次留痕**：跳过/整批回滚/人工回滚/争用/空钥/漂移/重启恢复均落事件流，回滚详情旁可核对；同流活跃钥条以部分唯一索引兜底，回滚后钥条释放可再入库。

| 接口 | 说明 |
|------|------|
| `GET/POST /api/policy` | 查看/钉死当日幂次策略 |
| `POST /api/flows/<id>/landing` | 开入库批（body：`strategy`、`keys[]`、可选 `operator`） |
| `GET /api/batches`、`GET /api/batches/<id>` | 入库列表（横排跳过条数/已回滚次数/策略标题）与批次详情 |
| `POST /api/batches/<id>/rollback` | 开回滚单（body：`reason`、可选 `operator`） |
| `GET /api/rollbacks/<id>` | 回滚详情：回滚单正文 + 幂次/争用痕迹 |

后台耗时可用环境变量 `LANDER_DELAY`、`ROLLBACK_DELAY`（秒）调大以便观察在途与争用。
